# QueryPilot 实施计划

## 范围与原则

- 独立个人项目：工具调用 Agent + 可执行评测 + 后续 Agentic RL。
- 先做可运行任务和失败分析，再决定训练；不因计划包含 GRPO 就提前租 GPU。
- 不依赖 LangGraph，不做万能 Agent、多 Agent、长期记忆或复杂前端。
- 所有阶段都是待完成任务，不预设效果提升。
- 参考答案、参考 SQL 和期望结果只供验证与奖励使用，不进入 Agent 可见上下文。

## 1. 数据与任务

状态：待开始。

- 选择公开数据库问答数据，核查下载方式、许可和参考 SQL 的可执行性。
- 首先准备少量 SQLite 数据库及问题，确认数据库内容可用于个人实验。
- 按数据库划分训练、开发与测试集，记录样本 ID、数据库 ID 与数据哈希。
- 固定结果比较规则：列、顺序、重复行、NULL 与数值容差；不能直接比较 SQL 文本。
- 单个数据库上偶然得到相同结果不等价于 SQL 语义正确，必要时人工审查。

验收：数据可加载，参考查询可运行，划分无数据库交叉；数据许可和来源有记录。

## 2. 轻量 Agent 执行器

状态：待开始。

工具范围：

- `list_tables()`：返回当前数据库允许查看的表。
- `get_schema(table_names)`：返回字段、类型及关联关系。
- `execute_sql(sql)`：在受限只读环境中执行查询，返回结果或结构化错误。

实现模型接口、工具 schema、消息历史、tool call ID 对齐、参数校验、执行反馈和终止条件。模型根据工具结果选择后续动作，不固定写死调用顺序。

执行限制：只读连接和权限控制、禁止任意文件或外部数据库访问、查询超时、结果行数限制、交互轮数预算、重复调用记录。不仅凭 SELECT 前缀判断 SQL 安全性。

验收：完成“查看结构 -> 查询 -> 错误反馈 -> 修正 -> 最终回答”；未知工具、错误参数、超时、预算耗尽均有可测试行为。

## 3. 基线与失败分析

状态：待开始。

比较同一基座的一次生成 SQL 与多轮工具 Agent。报告模型配置、提示模板、数据库划分、推理预算与执行成本。

错误分类包括字段/表猜测错误、关联关系错误、SQL 语法错误、逻辑错误、重复无效调用及提前结束。

验收：每个结果可对应完整轨迹；明确哪些问题可通过工程修复，哪些适合训练。未发现清晰训练目标时，不进入 RL。

## 4. 轨迹 SFT

状态：待开始。

收集并验证成功轨迹，避免只因 SQL 可执行就判成功。构建多轮训练数据：模型生成的回答与工具调用是监督目标，用户输入和工具观察不计算 assistant loss。

采用小模型 LoRA 验证训练、保存与重新加载，模型规模及具体框架在硬件确定后选择。训练数据必须与测试数据库隔离。

验收：adapter 能重载；开发集比较训练前后任务正确率和调用成本，不假定一定改善。

## 5. Agentic RL

状态：待开始。

优先调研 Agent Lightning 的 SQL 示例，固定仓库版本和依赖后做小样本兼容测试，再决定实际后端。不同时搭建多套训练框架。

使用同一问题多条执行轨迹做 GRPO；先以执行结果正确性为核心奖励，再依据失败分析决定是否加入成本约束。不能为了减少调用而鼓励提前结束。

核查多轮动作 token、tool observation mask、行为策略 logprob、组内奖励标准差、KL、checkpoint 和恢复机制。模型生成动作计算策略 loss，工具观察不计算策略 loss。

验收：完成 smoke、参数更新、保存、恢复与固定评测后再扩规模。算力和训练耗时以 smoke 实测为准，不提前承诺显存可用或效果提升。

## 6. 最终比较与交付

状态：待开始。

对照：一次生成 SQL / 原始工具 Agent / SFT Agent / GRPO Agent。

指标：查询结果正确率、SQL 执行成功率、首次失败后的纠错成功率、工具调用次数、token 数、耗时、超时和越权尝试。报告样本数与预算；小测试集不作为强泛化证据。

交付：可运行脚本、配置、依赖版本、数据来源与划分说明、轨迹、评测结果和失败案例。每个指标关联唯一 run ID、模型或 checkpoint、代码版本与数据哈希。

## 实施节奏

业余时间暂按 3-4 周规划：数据 2-3 天、执行器 3-4 天、基线 2-3 天、SFT 3-4 天、RL 3-5 天、总结 2 天。以验收条件而非日期推进；阶段 1-3 完成前不购买 GPU。
